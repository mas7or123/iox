# Asset lighting walkthrough

The office has two independent jobs: light up the visible lens and put a controlled wash on the ceiling and wood slats. This is a worked example, not an inspection of the office. Tagged UI paths below are for Sollumz 2.9.1 unless noted.

## 1. Trace the fixture, receiver and room

1. **Start** in a copy of the placed blend, or import the deployed asset with its textures into a clean file. **Select** the lens mesh, not the MLO marker. In Edit Mode use Face Select with X-Ray off. In **Material Properties** choose the suspected slot, clear face selection and click **Select** to see every face assigned to it. Note whether it also selects the metal channel, ceiling or wood. Record the selected mesh, slot, shader and LOD for each lens, plus the actual ceiling and slat receivers. If the face itself is missing, check the drawable model and current LOD before touching lighting.
2. **Select** the root above that model in the Outliner. Confirm its Sollumz type is **Drawable** and log the matching YDR stem. In CodeWalker Project, inspect the placed YMAP MLO instance and the YTYP archetype it refers to. Follow the interior entity's archetype to the actual drawable. Inspect each owner separately if the strips are in different YDRs. Check whether other rooms or resources reuse the same drawable before replacing it. [Drawable layout](https://docs.sollumz.org/2.4/documentation) · [MLO setup](https://docs.sollumz.org/tutorials/creating-interiors/create-ytyp)
3. **Select** that MLO archetype in Sollumz and read **MLO → Rooms**, **Portals**, and **Entities**. On the fixture entity record its attached room, portal and entity set. Identify the player room separately through the walkable floor collision material's **Room ID** and the room bounds. Record the camera side and both room names at the doorway. Leave a shell that's deliberately attached to limbo alone. If a fixture is not an independent entity, trace its owner rather than assuming it has its own office assignment. [2.9.1 entity UI](https://github.com/Sollumz/Sollumz/blob/v2.9.1/ytyp/ui/entities.py) · [Collision Room ID](https://docs.sollumz.org/2.5/documentation/collisions.ybn)

| Finding | Files to change |
|---|---|
| Same drawable and placement. Texture is already available or embedded. | Replace only the YDR. Preserve its original stem, unrelated materials and any embedded collision. |
| External texture pixels or entry need updating. | Update YTD. Update YDR only if shader or sampler binding changes. |
| New archetype, dictionary link, office entity or room/portal/set attachment. | Update affected YTYP and corresponding assets. Keep existing transforms and unrelated flags. |
| Actual placement or streaming extents changed. | Update affected YMAP and dependency metadata such as _manifest.ymf if the resource uses it. |
| Floor collision Room ID is wrong. | Correct the affected YBN or embedded bounds only after proving the mismatch. |

[Archetype fields](https://docs.sollumz.org/2.6/documentation/archetype-definition.ytyp) · [Manifest and export FAQ](https://github.com/Sollumz/wiki/blob/main/support/faq.md)

## 2. Texture, convert, assign, verify

1. **Start** with the diffuser mesh selected in Object Mode. Open the 3D View sidebar with **N**, then **Sollumz Tools → Drawables → Shader Tools**. Select the opaque `emissive.sps` entry and click **Create Shader Material**. Give it a lens-only slot. For a conversion, first isolate the material to the lens and make the material datablock single-user. Select the target shader and use **Convert Active Material**. For an existing GTA shader the material panel also offers a **Change Shader** popover. Never convert all shell materials for a lens edit. [2.9.1 shader controls](https://github.com/Sollumz/Sollumz/blob/v2.9.1/ydr/ui.py) · [Material operations](https://github.com/Sollumz/Sollumz/blob/v2.9.1/ydr/operators/materials.py)
2. **Select** the new slot. In **Material Properties → Sollumz → Texture Parameters**, open or choose a real image for **DiffuseSampler**. Use a unique off-white diffuse image with headroom and usable mips, not a shared wood or trim texture. Opaque `emissive.sps` uses UV0. In Edit Mode select the visible lens faces only and click **Assign**. Deselect and hit the slot's **Select** to verify the assignment. Enable **Face Orientation** to confirm fronts face the viewer. Check UV0 in UV Editing against the actual image. Correct flipped normals, collapsed UVs and coincident faces if found. Repeat the slot and UV check on any lower LOD that should show the lens. [Opaque shader definition](https://github.com/Sollumz/szio/blob/0789b450d4321c7c61268103fcf88e888e81b91e/src/szio/gta5/Shaders.xml#L490-L515) · [Cfx LOD walkthrough](https://docs.fivem.net/docs/assets-manual/beginner-series/part-6/)
3. **Package** the sampler's pixels. For the isolated test, tick **Embedded** on just that sampler and verify the name and texture entry in the YDR. Blender packing alone doesn't make a GTA embedded texture. For the external route, leave **Embedded** off. In 2.9.1 use **Sollumz Tools → Texture Dictionaries** to import/select the existing YTD. In **Textures** add a list entry and select the source image for it. Export the dictionary, check the sampler name and entry match, and verify the archetype's **Texture Dictionary** link. Don't change other images to solve a diffuser problem. If the image displays in Blender but not FiveM, read back the streamed YDR/YTD before adjusting brightness. [Texture UI](https://github.com/Sollumz/Sollumz/blob/v2.9.1/ytd/ui.py) · [Texture export](https://github.com/Sollumz/Sollumz/blob/v2.9.1/ydr/ydrexport.py#L679-L809)
4. **Select** the lens slot and check **Value Parameters**. Only if the shader declares `emissiveMultiplier`, test the existing value and one controlled increase. For `emissive.sps`, test the defined default of 1 against 2 as an example, then read the value back from the export. If there's no declared multiplier, don't add one. Back off if the lens loses its edges. Self-emission lights the lens pixels, bloom spreads their brightness in screen space, and corona is a separate effect. None proves that a receiver is lit. [Shader definition](https://github.com/Sollumz/szio/blob/0789b450d4321c7c61268103fcf88e888e81b91e/src/szio/gta5/Shaders.xml#L490-L515) · [Light flags](https://docs.sollumz.org/2.6/documentation/lighting-.ydr/light-flags)

## 3. Prove one drawable Point, without the glowing lens

1. **Start** with the normal, non-emissive lens material. Put a small neutral-gray matte test card on a test mesh in the same office, using an opaque GTA material known to respond to lighting. Orient the normal toward the emitter. Place the 3D Cursor on the open-room side, not inside the trim, slats or cove. Example: 0.15 m out from the fixture and a card about 0.5 m away in clear sight. In 2.9.1 select the **Drawable** root in Object Mode and use **N → Sollumz Tools → Drawables → Light Tools → Point → Create Light**. Confirm the light is a descendant in the Outliner and is a GTA Point in Light Data. In 2.4.0 the same creation operator doesn't parent it or use the cursor. Place it explicitly and parent it: select the light, Shift-select the drawable root last, then **Ctrl+P → Object (Keep Transform)**. Always double-check that the origin didn't move and that the exported relative position matches. [2.4.0 creation](https://github.com/Sollumz/Sollumz/blob/v2.4.0/ydr/operators.py#L143-L158) · [2.9.1 creation](https://github.com/Sollumz/Sollumz/blob/v2.9.1/ydr/operators/lights.py)
2. **Calibrate** from a working stock fixture when possible. In a stock interior find a fixture next to a lit matte surface, trace its entity and use CodeWalker to read its native light record. Confirm `Type=Point` and compare a copy with and without that record in the test scene if ownership isn't obvious. Rule out an adjacent light or a YTYP Light Effect override. Record native Intensity, Falloff, exponent, RGB, fade distances and masks. A fixture model that only contains an emissive shader isn't a reference for direct light. No named stock fixture was verified for this guide. [Cfx stock asset exploration](https://docs.fivem.net/docs/assets-manual/beginner-series/part-2/)
3. **Select** the Point → **Light Data Properties → Sollumz → General Properties**. Enter native **Intensity**, **Falloff** and **Falloff Exponent** from the verified fixture first. Use stock range only if it fits the measured receiver distance. If no fixture record is available, a documented fallback is the 2.9.1 shipped **Point: Wall Light 1** preset, not a verified stock asset. Its source corresponds to native Intensity 1, Falloff 2, Falloff Exponent 64 and Light Fade Distance 20. The preset has a partial time mask. Set hours explicitly for the test. If it is too tight on the card, move the card closer, then try a lower exponent such as 8 at fixed range and intensity as a diagnostic only. A newly created `Default` preset can read as Intensity 0.02 with Falloff 40 in the tagged defaults. Don't assume that default represents a usable office light. Don't enter Blender wattage in the native Intensity field. 2.4.0 exposes Blender energy under the same label and exports it divided by 500. Compare XML values, not matching labels. [2.9.1 presets](https://github.com/Sollumz/Sollumz/blob/v2.9.1/ydr/gta5/presets/light_presets.json) · [2.9.1 conversions](https://github.com/Sollumz/Sollumz/blob/v2.9.1/ydr/properties.py#L349-L438) · [2.4.0 export](https://github.com/Sollumz/Sollumz/blob/v2.4.0/ydr/lights.py)
4. **Remove gates for the controlled test.** In **Misc Properties** set **Flashiness** to **Constant (0)** and leave the **Projected Texture Hash** empty. In **Time Flags** enable all 24 hourly bits and verify `0x00FFFFFF` or 16777215 in the serialized record. In **Flags** check that **Corona Only**, **Exterior Only**, **Only In Reflections**, sun-driven intensity, delayed-render and LOD-only options aren't restricting the baseline. Start with projection, culling plane and cast/static/dynamic shadows off. Zero corona size and volume intensity for the test. Read **Distance Properties → Light Fade Distance** separately from Falloff. Start with a known fade value that reaches the gameplay camera and compare inside versus across the doorway before reinstating intended interior-only flags. If there is an existing Light Effect extension, resolve it by Light ID before interpreting a changed result. [Light panel](https://github.com/Sollumz/Sollumz/blob/v2.9.1/ydr/ui.py#L299-L444) · [Time flags](https://github.com/Sollumz/Sollumz/blob/v2.9.1/sollumz_properties.py#L449-L477) · [Flashiness](https://docs.sollumz.org/documentation/lighting-.ydr/flashiness-values) · [Light Effect](https://github.com/Sollumz/wiki/blob/main/documentation/maps/entities/README.md)
5. **Export and compare A against C** using the [validation reference](troubleshooting-and-validation.md). The lens stays off and the card gains a localized bright patch. If not, check the streamed binary for the Point and check its placement and gates. Don't try to repair a missing patch by boosting emissive intensity, changing vertex tint or widening the whole office timecycle.

## 4. Put the wash where it belongs

**Start** with the proven Point kept in a separate test copy. In the wash copy remove that Point. Select the same drawable root and create one **Capsule** or **Spot** under it, with the same receiver and camera. Compare shapes one at a time.

| Target | Capsule | Broad Spot |
|---|---|---|
| Wood slats | Place the midpoint a little in front of the slat faces, under the strip. Align the capsule axis along the horizontal diffuser. Expect radial spill as well as the desired wash. Test a short run first. | Put the source forward of the slats and clear of the lip. Aim down and slightly into the exposed slat faces. Check for a top-to-bottom gradient with visible gaps, not round hotspots. |
| Recessed ceiling cove | Place one straight segment by the opening, not behind the cove lip. Align it parallel to that leg. Add other legs only after testing one. End neighboring segments short of the corner if overlap is hot. | Place the source at the opening and aim up and inward across the ceiling. Check the target is inside the cone. Test each leg separately before tuning the corner. |

- **Place and aim.** Under the light's **Sollumz** data confirm the native type. A newly created Capsule may appear as a Blender Point internally. In 2.9.1 exported Position is drawable-root-local for a non-bone fixture. Direction is normalized local −Z in that frame, and Tangent is +X. Inspect the local axes in Blender, then compare these values in the exported YDR/XML. Compare the world location after applying the entity and MLO transforms. Don't reset the placed MLO or apply unrelated transforms to make local numbers match. [Light serialization](https://github.com/Sollumz/Sollumz/blob/v2.9.1/ydr/lights.py#L143-L212)
- **Set the shape and falloff.** For Capsule, **Capsule Properties → Extent** edits X. CodeWalker's gizmo places the capsule's centerline endpoints at Position ± Direction × Extent.X/2, with Falloff as radius. Use that for aim and length, not as a game rendering result. For Spot, use **Spot Properties → Cone Inner Angle / Cone Outer Angle**. Example: 30°/55° in 2.9.1 is a starting trial, not Blender's full cone angle. The export clamps outer to 90° and inner to outer. If there is no patch, test with a card facing the emitter in clear air, inside range and in front of the cone. [CodeWalker capsule gizmo](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker/Rendering/Renderer.cs#L979-L1063)
- **Tune one variable at a time.** Move origin/aim first, then set extent or cone, falloff distance, exponent, intensity and color, then spacing. Adjust stand-off before boosting the slat wall. If a Capsule behaves like a point, verify exported type, Extent.X and Direction, then compare one short Capsule against one broad Spot. Use spaced Spots if that reproduces the desired wash more reliably. If a corner is too bright with both legs on, disable either leg and compare. Shorten the segments or reduce overlap before dimming the whole cove.
- **Contain leaks and add highlights last.** If light spills through walls or above the ceiling, try shorter reach, more useful source placement or an aimed Spot first. Only then try a culling plane, checking its normal, offset and which side is cut, or add static shadows to one fixture and compare. Check shadow near clip and fade, and avoid adding dynamic or high-resolution shadows to every fixture. Keep projection off unless intentionally using and verifying a texture. If the matte card works but the wood still looks flat, check slat normals, vertex colors and receiver material response in a separate comparison. Keep useful specular response and preserve dark gaps. [Light flags](https://docs.sollumz.org/2.6/documentation/lighting-.ydr/light-flags)

## 5. Read back the actual export and stream

1. **Select** the owner Drawable in Object Mode. In 2.9.1 use **File → Export → Export RAGE Assets → Limit to Selected** and choose **Target Formats → Native** and **Target Game Versions → Gen8 or Gen9**. Export to staging and read warnings. Preserve filenames and all unchanged dependencies. Native support for supported formats began in 2.8 through optional PyMateria, Windows-only at introduction. If native is unavailable, use **CW XML** and its DDS sidecars, then import XML in CodeWalker RPF Explorer in edit mode on a scratch archive and extract the resulting binary. Don't stream authoring XML or assume an old CodeWalker build reads/writes Gen9. [Export settings](https://github.com/Sollumz/Sollumz/blob/v2.9.1/sollumz_preferences.py) · [Sollumz releases](https://github.com/Sollumz/Sollumz/releases)
2. **Inspect** the deployment copy. Log a hash and open the compatible binary with CodeWalker's RPF Explorer **File → Open Folder... → Export XML...**, or reimport that exact binary using Blender **File → Import → Import RAGE Assets** into a clean file. Compare the active LOD geometry's shader index, shader filename and render bucket, DiffuseSampler name, resolved pixels/mips and supported multiplier. Compare `Lights` count, type, Position/Direction/Tangent, extent/angles, RGB, Intensity, Falloff/exponent, Flashiness, time/visibility flags, fade distances, culling, projection, corona, shadows, and bone/light IDs. Treat an unsupported reader as an inspection failure, not proof a record is missing. [CodeWalker menus](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker/ExploreForm.Designer.cs) · [Binary and XML schema](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/Resources/Drawable.cs)
3. **Inspect** the placed office only when symptoms point there. If the mesh disappears, check drawable/archetype bounds and LOD, room bounds, collision floor Room ID, portal corner winding/normal, From/To rooms, attachments, entity-set state and any closed-door visibility flag. Compare against an unchanged working opening. If only the light disappears, check its flags/fades and owning entity before editing the portal. Check timecycle independently if the whole room's exposure changes. Record any dependency changes, including _manifest.ymf if used. [MLO setup](https://docs.sollumz.org/tutorials/creating-interiors/create-ytyp) · [Doorway failure case](https://forum.cfx.re/t/problem-with-interior-not-loading/5126770)
4. **Check** the selected resource tree. Legacy uses `stream/`. Enhanced uses `stream_enhanced/` *instead of* `stream/` when the former exists, not as a per-file overlay. If no Enhanced folder exists, Enhanced uses `stream/`, which doesn't prove its contents are compatible. Provide the complete required streamed dependencies per generation. Alchemist on Windows 11 converts YDR, YTD, YFT, YPT and YDD. It does not list YTYP, YMAP or YBN for conversion. Inspect existing `fxmanifest.lua` for map registration and explicitly registered paths such as `DLC_ITYP_REQUEST` where used. Check other started resources for duplicate stems, archetype hashes and stale variants. Restart the staging resource and reconnect if needed. If the stream identity remains in doubt, temporarily put a distinctive image on the same lens and prove that the intended build is visible. Remove it before A/B. [Cfx Enhanced folders](https://docs.fivem.net/docs/developers/legacy-vs-enhanced/#stream_enhanced-folder) · [Alchemist](https://docs.fivem.net/docs/alchemist/) · [Data files](https://docs.fivem.net/docs/game-references/data-files/)

## 6. Finish the office

Run the [four-state test](troubleshooting-and-validation.md) with the Point, then the selected wash. Finish with both fixtures enabled, test from both sides of the doorway, and remove the diagnostic card. Require the lens, slats and ceiling to pass separately before calling the overall office done. See [evidence and version notes](tutorial-evidence.md) for provenance and limits.
