# Believable game props

Work on the requested prop and preserve its placement, footprint, palette, and design intent unless the user authorizes a change. Review without editing. For authorized creation or revision, work on a copy or branch until the pilot is accepted. Do not overwrite source assets or roll a pilot out across the set without evidence.

## Workflow

1. **Establish the target and evidence.** Pick a real reference that matches the object, construction, finish, and era. Record its URL, dimensions or scale anchor, intended materials, target engine/build, normal and nearest player views, and any project budgets. Use distance, camera/FOV, and approximate on-screen size when available. Write acceptance criteria before testing. Label assumptions and unknowns. Inspect every available attachment and representative workspace assets, import/export settings, and known-good peers. For each prop, record the visible symptom, plausible causes, a check that would distinguish them, and the highest-impact conditional fix. A screenshot can support a visual judgment, not confirm topology, shader settings, export behavior, or lighting setup. Treat narrative reports as leads for visual and runtime checks, not as substitutes for inspectable captures or test artifacts. For an unseen prop, write “not shown / unverified.” Keep user notes separate from direct observations.
2. **Check form in neutral gray.** Turn off image textures, normals/bump, decals, and colored effects. Use a neutral light and compare silhouette, proportions, construction boundaries, edge highlights, and contact at the normal view and close-up. For upholstery, use front, three-quarter, and side/profile as needed. Verify loft, crown, front roll, support contact, and intended cushion gaps before adding surface detail. If the outline, gap, or contact is wrong, fix shape or fit first. If only face gradients are wrong, isolate shading normals before changing topology.
3. **Check materials side by side.** Under one shared light and exposure, separate materials by their boundaries and light response, not just color. Verify relevant fabric, leather, plastic, glass, wood, stone, and metal against the intended finishes. Compare normal play and close-up. Check world-space grain/vein scale, UV direction and stretching, mip readability, reflection response, and any required transparency. Keep distinct-looking materials visually separate without assuming each needs its own draw call. If form reads in gray and the assigned finish does not, test one map or material change at a time.
4. **Pilot one foreground prop in the actual scene.** In review-only work, specify the pilot and request missing captures without making changes. For authorized revisions, record a baseline and export one candidate using the verified project pipeline. Match placement, camera/FOV, lighting, exposure, and display state for before/after. Check the regular player path, nearest angle, grazing light, LOD changes, texture mips, and relevant bounds, collision, or animation. Inspect the exported asset and profile cost against project limits where tools allow. If gray and preview look right but runtime differs, isolate bindings, normal conventions, shader behavior, and scene lighting with a known-good runtime asset before remodeling. If access is missing, report “not verified in-game” and name the exact prop, scene/view, and comparison to run. Do not claim the pilot was shipped or the set updated.
5. **Report each applicable check.** Use `Prop | Check | Pass / Fail / Not verified | Evidence | Next fix or test`. Pass only when direct evidence meets that specific criterion and scope. Fail only the criterion the evidence contradicts. Mark missing or ambiguous evidence Not verified, with a concrete next test. An image can fail a visual criterion for its shown view while the cause and runtime remain Not verified. A Blender pass is not an in-game pass. Name artifacts, views, or measurements and prioritize what players will actually notice. Use machine-readable reports or direct inspection to verify numerical and structural checks within their stated scope. A material-slot count alone does not establish runtime draws or a performance failure.

## Choose detail that survives play

Put profile, fit, spacing, edge breakup, and visible parallax in geometry if they read at the intended view. Use baked normals for shallow relief that changes lighting without changing the outline. Use color or masks for markings and subtle variation. Drop detail that aliases, shimmers, or disappears. Use reference proportions, a known-good peer, and measured project/frame cost instead of universal bevel widths, triangle counts, or shader values.
